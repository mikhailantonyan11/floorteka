# Предсказание отмены заказа

Бинарная классификация: будет ли заказ отменён (`is_cancelled`: 0/1).

Метрика: **ROC-AUC**. Баллы: `max(0, AUC − 0.55) / 0.45`.

## Данные

- `data2/train.csv` — `id, delivery_time, order_price, customer_type, distance, restaurant_rating, is_cancelled`
- `data2/test.csv` — те же признаки без целевой переменной
- `data2/submission.csv` — готовый сабмит (вероятности отмены)

## Разведочный анализ

- Пропусков и дублей нет, 47 676 строк train / 11 916 строк test
- Целевая переменная несбалансирована: 22.5% отменённых заказов
- Корреляции с целевой переменной слабые, но стабильные и монотонные:
  - `delivery_time` (+0.083) — чем дольше доставка, тем выше шанс отмены
  - `distance` (+0.082) — то же для расстояния
  - `customer_type` — новые клиенты отменяют чаще (24.1% против 14.2% у постоянных)
  - `restaurant_rating` (−0.028) — слабая обратная связь
  - `order_price` — сигнала практически нет

## Подход

1. **Предобработка:** `customer_type` (new/regular) → бинарный признак `is_regular`. Признак `order_price` исключён из финальной модели — он не показал предсказательной связи с целевой переменной ни в разведочном анализе, ни в кросс-валидации (см. ниже).
2. **Признаки:** `delivery_time`, `distance`, `restaurant_rating`, `is_regular`.
3. **Модель:** ансамбль (усреднение вероятностей) трёх алгоритмов:
   - **GAM-подобный подход**: изотоническая регрессия по каждому признаку отдельно (учитывает реальную, монотонную, но нелинейную форму зависимости — например, резкий скачок риска отмены при рейтинге ресторана ниже ~3.5) + логистическая регрессия поверх преобразованных признаков
   - **XGBoost с монотонными ограничениями** (направление ограничений задано по знаку связи каждого признака с целью — это не даёт модели переобучаться на шуме в разреженных областях признакового пространства)
   - **CatBoost**

## Проверка потолка качества

Была проведена расширенная проверка, чтобы убедиться, что модель не оставляет качество "на столе":
- Полиномиальные и binned-признаки для логрегрессии — не лучше сырых признаков
- Инженерные признаки (скорость, residual времени доставки от расстояния, взаимодействия с типом клиента) — не улучшают AUC
- Неограниченный по глубине Random Forest не превышает потолок ~0.58
- Сетка гиперпараметров XGBoost/LightGBM (глубина, learning rate, число деревьев) — лучший результат в том же диапазоне
- Нейросеть (MLP) — хуже линейных моделей
- **Повторная кросс-валидация (5×4 = 20 фолдов)**: разброс ROC-AUC между фолдами (std ≈ 0.0075) на порядок больше, чем разница между разными моделями/подходами (< 0.002) — это статистически подтверждает, что ~0.586 является достижимым пределом для данного набора признаков, а не следствием неудачного выбора модели

Единственный найденный содержательный, но не переобучающий эффект — нелинейный порог
по `restaurant_rating`: при рейтинге < 3.5 риск отмены заметно выше (31% против 22%),
что и учитывает изотоническая регрессия в GAM-компоненте ансамбля.

## Результат (5-fold CV, OOF)

| Модель | ROC-AUC |
|---|---|
| GAM (изотоническая регрессия + LogReg) | 0.5861 |
| XGBoost (монотонный) | 0.5852 |
| CatBoost | 0.5857 |
| **Ансамбль (среднее)** | **0.5859** |

Ориентировочный балл: `(0.5859 − 0.55) / 0.45 ≈ 0.080`.
